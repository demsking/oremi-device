Oremi Device captures microphone audio and connects it to Oremi services:

- **Ohunerin** detects wake words and environmental sounds.
- **Andika** transcribes speech after Ohunerin detects a wake word.
- **MQTT** exposes events, device controls, availability, and Home Assistant
  discovery entities.

The application monitors audio hardware while it runs. It can switch to another
compatible microphone when the active device disappears and switch back when a
preferred device becomes available again.

## Requirements

- Python 3.12, or Docker
- An MQTT broker
- Running Ohunerin and Andika servers
- A microphone unless `--no-microphone` is used
- Optional speaker hardware for the MQTT speaker controls

## Installation

### From PyPI with pip

```bash
pip install oremi-device
```

### From PyPI with uv

```bash
uv tool install oremi-device
```

## Quick Start

### Using pip-installed package

After installation, you can run the device directly:

```bash
oremi-device start \
  --node-id living-room \
  --ohunerin-host localhost \
  --andika-host localhost \
  --mqtt-broker localhost
```

### Using Docker

The `start` command requires a node ID and the addresses of the Ohunerin,
Andika, and MQTT services:

```bash
docker run --rm -it \
  --network host \
  --device /dev/snd:/dev/snd \
  demsking/oremi-device start \
  --node-id living-room \
  --ohunerin-host 127.0.0.1 \
  --andika-host 127.0.0.1 \
  --mqtt-broker 127.0.0.1
```

`--network host` is used here so the container can reach services bound to the
host. Use Docker service names instead when all services share a Docker
network. PulseAudio installations may also need the PulseAudio socket and
cookie mounted into the container.

## Command Line

General syntax:

```text
oremi-device [-h] [-v] {start} ...
```

| Option            | Description                   |
| ----------------- | ----------------------------- |
| `-h`, `--help`    | Show help.                    |
| `-v`, `--version` | Show the application version. |

### `start`

```text
oremi-device start [options]
```

Here are the command-line options for `oremi-device start` formatted as a list:

**Required Options**

- `-n, --node-id ID` (Required): Unique node identifier. It scopes the MQTT client and device control topics.
- `--ohunerin-host HOST` (Required): Ohunerin server host.
- `--andika-host HOST` (Required): Andika server host.
- `--mqtt-broker HOST` (Required): MQTT broker host.

**Server Connection Options**

- `--ohunerin-port PORT` (Optional, default: `5023`): Ohunerin server port.
- `--andika-port PORT` (Optional, default: `5315`): Andika server port.
- `--mqtt-port PORT` (Optional, default: `1883`): MQTT broker port.
- `--mqtt-username USER` (Optional): MQTT username.
- `--mqtt-password PASSWORD` (Optional): MQTT password.
- `--mqtt-topic TOPIC` (Optional, default: `oremi/device`): Base topic for events, availability, and controls.
- `--cert-file PATH` (Optional, default: Insecure connections): CA certificate used for TLS connections to both services. This changes their WebSocket and HTTP URLs to `wss` and `https`.

**Audio Device Options**

- `-i, --device-index INDEX` (Optional, default: Auto): Preferred microphone index.
- `-d, --device NAME` (Optional, default: Auto): Preferred microphone name. This takes precedence over `--device-index`.
- `--no-microphone` (Optional, default: Microphone enabled): Disable microphone initialization and audio capture.
- `--no-speaker` (Optional, default: Speaker enabled): Disable speaker initialization and speaker MQTT controls.

**Behavioral Options**

- `-l, --language LANGUAGE` (Optional, default: `fr`): Language sent to Ohunerin when the service connection is created.
- `--delay SECONDS` (Optional, default: `3`): Suppress duplicate sound events for this period and then publish a clearing event. It is also used as the Andika MQTT message expiry interval.
- `--conversation-timeout SECONDS` (Optional, default: `15`): Stop capturing speech and return to wake-word mode when Andika does not return a final result within this period.
- `--config PATH` (Optional, default: Built-in defaults): JSON component configuration file.

**Discovery Options**

- `--no-mqtt-discovery` (Optional, default: Discovery enabled): Disable Home Assistant MQTT discovery.
- `--mqtt-discovery-prefix PREFIX` (Optional, default: `homeassistant`): Home Assistant discovery topic prefix.

Run `oremi-device start -h` for the help generated by the installed version.

## Runtime Behavior

At startup, Oremi Device:

1. Validates the optional JSON configuration.
2. Initializes the preferred microphone and speaker when enabled.
3. Connects to MQTT and subscribes to this node's control topics.
4. Starts the Ohunerin and Andika components.
5. Streams microphone audio continuously to Ohunerin.
6. Starts streaming audio to Andika after a wake-word event and stops after
   Andika returns a final transcription or the conversation timeout expires.

Ohunerin and Andika reconnect with exponential backoff when their WebSocket
connections fail. The application also polls for audio-device changes and
updates Home Assistant discovery options when devices appear or disappear.

The device enable and microphone mute controls pause audio streaming without
stopping the service connections. A language command updates the retained MQTT
state and reconnects Ohunerin with the newly selected language.

## Configuration File

**Configuration File Overview**

- The file passed to `--config` is a JSON object with component settings nested under `components`
- Both components start even when their sections are omitted, using the defaults listed below
- Invalid JSON, invalid types, or an unsupported Andika model cause startup to exit with an error

**Ohunerin Component Settings**

- `components.ohunerin.threshold` (Optional, default: `0.85`): Minimum confidence score accepted for Ohunerin sound and wake-word events.

**Andika Component Settings**

- `components.andika.model` (Optional, default: `vosk-model-small-fr-0.22`): Vosk model identifier sent to Andika. The value must be one of the models supported by the application and server.
- `components.andika.samplerate` (Optional, default: `16000`): Audio sample rate sent to Andika.

**Example Configuration**

```json
{
  "components": {
    "ohunerin": {
      "threshold": 0.85
    },
    "andika": {
      "model": "vosk-model-small-fr-0.22",
      "samplerate": 16000
    }
  }
}
```

Both components start even when their sections are omitted, using the defaults
above. Invalid JSON, invalid types, or an unsupported Andika model cause startup
to exit with an error.

The schema currently accepts a top-level `language` field, but startup language
is taken from `--language`; the configuration field does not override the CLI
value.

Mount a configuration file into the Docker container before referencing it:

```bash
docker run --rm -it \
  --network host \
  --device /dev/snd:/dev/snd \
  -v "$PWD/config/device.json:/config/device.json:ro" \
  demsking/oremi-device start \
  --config /config/device.json \
  --node-id living-room \
  --ohunerin-host 127.0.0.1 \
  --andika-host 127.0.0.1 \
  --mqtt-broker 127.0.0.1
```

## MQTT

Examples below use the default base topic `oremi/device` and a node ID of
`living-room`.

### Events

| Topic suffix            | Payload                   | Notes                                                                                                        |
| ----------------------- | ------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `available`             | `online` or `offline`     | Retained availability state.                                                                                 |
| `sound`                 | JSON detection event      | Environmental sounds accepted by the configured threshold. Duplicate labels are suppressed during `--delay`. |
| `wakeword`              | JSON detection event      | Wake-word events also activate Andika transcription.                                                         |
| `transcription/partial` | UTF-8 text                | Non-retained partial Andika result, QoS 1.                                                                   |
| `transcription/text`    | UTF-8 text                | Non-retained final Andika result, QoS 1. This is also the Home Assistant transcription sensor state topic.   |
| `microphone/state`      | Microphone name or `None` | Retained active microphone state.                                                                            |

Ohunerin detection messages use this shape. The `sound` value is converted to a
lowercase slug before publication:

```json
{
  "type": "sound",
  "sound": "baby-cry-infant-cry",
  "score": 0.91,
  "date": "2026-06-19T12:04:10.123456"
}
```

After the delay expires, the service publishes a retained clearing message with
`"sound": "..."` when no event of that type remains active.

### Device Controls

| Command topic                                         | State topic                                             | Payload                                                   |
| ----------------------------------------------------- | ------------------------------------------------------- | --------------------------------------------------------- |
| `oremi/device/device/living-room/switch/set`          | `oremi/device/device/living-room/switch/state`          | `ON` enables audio processing; `OFF` disables it.         |
| `oremi/device/device/living-room/language/set`        | `oremi/device/device/living-room/language/state`        | A UTF-8 language string. Discovery offers `fr` and `en`.  |
| `oremi/device/device/living-room/microphone/set`      | `oremi/device/microphone/state`                         | A microphone name exposed by discovery.                   |
| `oremi/device/device/living-room/microphone/mute/set` | `oremi/device/device/living-room/microphone/mute/state` | `ON` mutes capture; `OFF` unmutes it.                     |
| `oremi/device/device/living-room/speaker/set`         | `oremi/device/device/living-room/speaker/state`         | A speaker name exposed by discovery.                      |
| `oremi/device/device/living-room/speaker/mute/set`    | `oremi/device/device/living-room/speaker/mute/state`    | `ON` mutes the speaker; `OFF` unmutes it.                 |
| `oremi/device/device/living-room/speaker/volume/set`  | `oremi/device/device/living-room/speaker/volume/state`  | Integer percentage from `0` to `100`.                     |
| `oremi/device/device/living-room/player/play/set`     | `oremi/device/device/living-room/player/state`          | An HTTP or HTTPS audio URL; state is `playing` or `idle`. |
| `oremi/device/device/living-room/player/stop/set`     | `oremi/device/device/living-room/player/state`          | Any payload stops playback.                               |

The microphone state topic is `oremi/device/microphone/state`; unlike the other
control states, it is not nested below the node-specific prefix.

For example, disable processing for this node with:

```bash
mosquitto_pub \
  -t oremi/device/device/living-room/switch/set \
  -m OFF
```

## Logging

Logging is configured only through environment variables:

**Environment Variables:**

- `LOG_LEVEL` – Logging severity level. One of `DEBUG`, `INFO`, `WARNING`, `ERROR`, or `CRITICAL`. Invalid values fall back to `INFO`. Default: `INFO`
- `LOG_FILE` – File path for log output. Must be writable by the process. Default: Standard error (stderr)

**Example:**

```bash
LOG_LEVEL=DEBUG LOG_FILE=/var/log/oremi-device.log oremi-device start \
  --node-id living-room \
  --ohunerin-host localhost \
  --andika-host localhost \
  --mqtt-broker localhost
```

**Docker example:**

```bash
docker run --rm -it \
  --network host \
  --device /dev/snd:/dev/snd \
  -e LOG_LEVEL=DEBUG \
  -e LOG_FILE=/var/log/oremi-device.log \
  -v /var/log:/var/log \
  demsking/oremi-device start \
  --node-id living-room \
  --ohunerin-host 127.0.0.1 \
  --andika-host 127.0.0.1 \
  --mqtt-broker 127.0.0.1
```

**Notes:**

- Setting `LOG_LEVEL=DEBUG` provides verbose output useful for troubleshooting
- When using Docker, ensure the log directory is mounted with `-v` to persist logs outside the container
- If `LOG_FILE` points to a directory that doesn't exist, the process will fail to start

## Home Assistant

MQTT discovery is enabled by default. On MQTT connection, Oremi Device publishes
retained discovery configurations below `homeassistant` for:

- enabled state and language
- microphone selection and mute state
- speaker selection, mute state, and volume
- Ohunerin wake-word and sound sensors
- Andika transcription sensor

The entities share one device identifier derived from `--node-id`. Available
microphones and speakers are included as select options. When microphone or
speaker support is disabled, the corresponding retained discovery configs are
cleared.

Use `--no-mqtt-discovery` to disable discovery or
`--mqtt-discovery-prefix` when Home Assistant uses a custom prefix.

### Media Player

Home Assistant does not provide a native MQTT media-player platform. To expose
Oremi as a real `media_player` with the `speaker` device class, install the
bundled integration by copying `custom_components/oremi_device` into the Home
Assistant configuration directory and restart Home Assistant:

```text
config/
└── custom_components/
    └── oremi_device/
```

With the default `oremi/device` MQTT topic, the integration discovers each
running node and Home Assistant offers it for setup. For a custom base topic,
add **Oremi Device Player** from **Settings > Devices & services**, then enter
the node ID and MQTT base topic.

The resulting `media_player` supports Home Assistant TTS and audio media-source
URLs, stop, mute, and volume controls. Playback requires `ffmpeg`; it is included
in the Docker image and must be installed separately when running from source.
